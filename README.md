# IMPERIAL RADIO (Fastify + TypeScript)

Минимальное веб‑приложение для онлайн‑радио: сайт с плеером, прокси аудио‑потока, “Сейчас играет”, админ‑загрузка. Интерфейс RU, тёмная тема.

## Установка

Нужен Node.js 22.5 или новее (приложение использует встроенный `node:sqlite`). Для локального запуска сайта достаточно Node.js; для полного радио дополнительно потребуются Icecast2, Liquidsoap 2.x, FFmpeg и MediaMTX.

```
npm ci
cp .env.example .env
npm run build
npm start
```

В PowerShell скопируйте конфигурацию командой `Copy-Item .env.example .env`. Перед первым запуском задайте в `.env` собственные `ADMIN_USER`, сильный `ADMIN_PASS` и случайный `LIVE_INGRESS_PASSWORD`; не публикуйте и не добавляйте `.env` в Git. Первые учётные данные администратора создаются из этих переменных только при инициализации пустой базы. При разработке используйте `npm run dev`, а перед публикацией запускайте `npm test` и `npm run build`.

Основные переменные окружения:

| Переменные | Назначение |
|---|---|
| `HOST`, `PORT`, `NODE_ENV` | Адрес, порт и режим веб-приложения; за reverse proxy обычно оставляют `127.0.0.1:3000`. |
| `ICECAST_BASE`, `ICECAST_MOUNT`, `ICECAST_STATUS_PATH` | Локальный Icecast, основной mount потока и путь к статусу. |
| `ICECAST_STATUS_USER`, `ICECAST_STATUS_PASS` | Необязательная авторизация для чтения статуса Icecast. |
| `MUSIC_DIR`, `JINGLES_DIR`, `TMP_DIR`, `DATA_DIR` | Каталоги музыки, джинглов, временных файлов и базы SQLite. |
| `ADMIN_USER`, `ADMIN_PASS` | Учётная запись главного администратора при первом старте пустой базы. |
| `LIQUIDSOAP_HOST`, `LIQUIDSOAP_PORT` | Локальный telnet-интерфейс Liquidsoap. |
| `LIVE_INGRESS_PASSWORD` | Общий секрет между приложением, FFmpeg и входами Harbor Liquidsoap; задайте тот же секрет в конфигурации Liquidsoap. |
| `BROADCAST_RTMP_BASE_URL`, `BROADCAST_WHIP_BASE_URL`, `BROADCAST_ICECAST_BASE_URL` | Публичные адреса входов для OBS, браузерного микрофона и BUTT. |
| `ICECAST_INGEST_HOST`, `ICECAST_INGEST_PORT` | Внутренний HTTP listener приложения; по умолчанию `127.0.0.1:8006`. |
| `ICECAST_RAW_INGEST_HOST`, `ICECAST_RAW_INGEST_PORT` | TCP-мост Icecast SOURCE для BUTT; по умолчанию локальный `127.0.0.1:8007`. |
| `FFMPEG_PATH`, `MAX_UPLOAD_MB`, `NOWPLAYING_CACHE_MS`, `LOG_LEVEL` | Путь к FFmpeg, лимит загрузки, TTL метаданных и уровень логирования. |
| `IMPERIALRADIO_APP_URL` | Необязательный адрес веб-приложения для callback-скрипта MediaMTX; по умолчанию `http://127.0.0.1:3000`. |

## Аудиоэфир

`npm start` запускает веб-приложение и его DJ-входы, но не сами службы аудиоэфира. Для полного радио отдельно установите Icecast2, Liquidsoap 2.x, FFmpeg и MediaMTX; веб-приложение не устанавливает и не запускает их автоматически. `liquidsoap.liq` использует встроенный MP3-кодер Liquidsoap. На Linux пути плейлистов должны совпадать с `MUSIC_DIR` и `JINGLES_DIR` (по умолчанию `/radio/music` и `/radio/jingles`); каталоги музыки и `DATA_DIR` должны быть доступны пользователю службы.

| Порт по умолчанию | Служба | Доступ |
|---|---|---|
| `3000/tcp` | Веб-приложение | Только loopback за HTTPS reverse proxy. |
| `8000/tcp` | Icecast (выход эфира и статус) | Только loopback; слушателям отдавайте `/stream` через сайт. |
| `8005/tcp` | Liquidsoap Harbor (`/dj-live`, `/dj-mic`) | Только loopback/firewall; не открывайте наружу. |
| `8006/tcp` | Внутренний HTTP DJ-ingress | Только loopback. |
| `8007/tcp` | Raw TCP-мост BUTT | По умолчанию loopback; для удалённого BUTT назначьте доступный извне порт. |
| `1234/tcp` | Liquidsoap telnet | Только loopback, не публикуйте в интернет. |
| `1935/tcp` | MediaMTX RTMP (OBS) | Открывайте только если используете OBS. |
| `8189/udp` | MediaMTX WebRTC | Открывайте для браузерного микрофона. |

Для production разместите `DATA_DIR` вне каталога проекта и настройте права на него, музыкальные каталоги и конфигурацию служб. Не заменяйте production `.env`, конфигурацию Liquidsoap или MediaMTX файлами из репозитория без переноса секретов и серверных путей.

## DJ и администрирование

При первом запуске приложение переносит `ADMIN_USER` и `ADMIN_PASS` из `.env` в локальную базу данных как учётную запись главного администратора; значение пароля `change_me` намеренно не мигрируется. Установите собственный сильный `ADMIN_PASS` до первого запуска. Пользователи, сессии и личные плейлисты хранятся в SQLite (`DATA_DIR/radio.sqlite`), пароли и токены сессий в открытом виде не сохраняются.

Диджеев создаёт главный администратор в панели `/admin`. Диджей входит через `/login`, получает доступ только к своим плейлистам, может добавлять треки из общей музыкальной библиотеки и занимать единый слот плейлистного эфира. Загруженные DJ треки помещаются в общую библиотеку. Во время плейлистного эфира отдельная очередь показывает следующие треки; DJ может добавлять, удалять и переставлять их без прерывания текущего трека. Очередь приватна для владельца эфира. При перезапуске приложения или остановке эфира активный слот и очередь DJ сбрасываются. Перед запуском новой версии обновите конфигурацию Liquidsoap, сохранив production-секреты и Linux-пути: требуются очередь `dj_queue`, входы `/dj-live` и `/dj-mic`, а также команды управления очередью, микрофоном и громкостью.

Режимы выхода DJ в эфир: личный плейлист/очередь, OBS по RTMP и BUTT по Icecast SOURCE. Во время плейлистного эфира DJ может отдельно включать микрофон браузера по WHIP/WebRTC: музыка продолжает играть и становится тише примерно на 3 dB; ползунок в студии регулирует общую громкость потока. Для внешних источников нужны FFmpeg и MediaMTX; пример конфигурации MediaMTX находится в `mediamtx.yml`. MediaMTX и Liquidsoap подключаются к локальному приложению, а уникальные путь и временный пароль выдаются DJ при каждом эфире. Liquidsoap автоматически переключается на AutoDJ при завершении внешнего источника; публичный веб-плеер повторно подключается после сетевого сбоя, если слушатель уже нажал «Играть» и сам не поставил его на паузу. Для работы в фоне нужно сначала разрешить воспроизведение нажатием кнопки: браузеры запрещают автозапуск звука.

Главный администратор может просматривать статус и отдельно перезапускать AutoDJ (Liquidsoap), Icecast и MediaMTX в панели `/admin`. На Linux установите helper `deploy/imperialradio-service-control.py` в `/usr/local/libexec/` с владельцем `root:root` и правами `0755`, а socket и template unit из `deploy/` — в `/etc/systemd/system/` с владельцем `root:root` и правами `0644`. Затем выполните `systemctl daemon-reload` и `systemctl enable --now imperialradio-service-control.socket`. Socket доступен только пользователю приложения; root helper принимает лишь ID трёх разрешённых служб и выполняет фиксированные команды без shell. Это сохраняет `NoNewPrivileges` для приложения. Перезапуск Icecast прерывает подключения слушателей, а MediaMTX — публикации OBS/микрофона.

Панели используют адаптивную боковую навигацию и отдельные защищённые страницы: `/admin/djs`, `/admin/music`, `/admin/uploads`, `/admin/services` и `/dj/studio`, `/dj/queue`, `/dj/playlists`, `/dj/library`, `/dj/upload`. Библиотека и загрузка музыки в DJ-панели находятся на разных страницах. Для перехода между страницами проверяется роль пользователя; неизвестные разделы возвращают `404`.

### Настройка аудиовхода DJ

1. В `.env` задайте случайный `LIVE_INGRESS_PASSWORD` и укажите **то же значение** как пароль обоих входов `input.harbor` в `liquidsoap.liq`. Это внутренний пароль, не пароль DJ. Не используйте значение по умолчанию в production.
2. Запустите Liquidsoap с обновлёнными входами Harbor `127.0.0.1:8005/dj-live` и `127.0.0.1:8005/dj-mic`; приложение использует второй mount для наложения голоса на плейлист. В Liquidsoap 2.0.2 Harbor может слушать на всех интерфейсах, поэтому обязательно запретите входящие подключения к TCP-порту `8005` с внешних интерфейсов. На VPS это обеспечивается отдельным nftables-правилом и systemd-службой `imperialradio-ingress-firewall`. Запустите FFmpeg и задайте `FFMPEG_PATH`, если бинарник не находится в `PATH`.
3. Запустите приложение через `npm start`, затем MediaMTX из корня проекта с конфигурацией `mediamtx.yml` (например, `mediamtx mediamtx.yml`). Его callbacks должны иметь доступ к приложению на `127.0.0.1:3000`; `IMPERIALRADIO_APP_URL` можно задать для `scripts/mediaGatewayNotify.mjs`, если используется другой адрес. Медиа-пути RTSP/API должны оставаться локальными.
4. Для OBS откройте RTMP порт MediaMTX (по умолчанию 1935) и задайте `BROADCAST_RTMP_BASE_URL`. В OBS должен быть включён аудиоканал. Для браузерного микрофона настройте HTTPS reverse proxy для WHIP на порт 8889, задайте публичный `BROADCAST_WHIP_BASE_URL`, укажите публичный адрес в `webrtcAdditionalHosts` и откройте UDP порт 8189. Микрофон доступен браузеру только через HTTPS или localhost.
5. Для удалённого BUTT задайте `ICECAST_RAW_INGEST_HOST=0.0.0.0`, выберите свободный публичный TCP-порт в `ICECAST_RAW_INGEST_PORT` и установите `BROADCAST_ICECAST_BASE_URL` на `http://<адрес-сервера>:<порт>`. Откройте только этот порт в firewall. Raw TCP-мост принимает Icecast source-протокол и преобразует его для внутреннего HTTP listener приложения; не проксируйте его через HTTP location Nginx. Вход рассчитан на непрерывный запрос и не ограничивается стандартным 300-секундным таймаутом Node.js. Внешний вход работает без TLS: имя пользователя и временный пароль передаются открыто. Используйте защищённую TCP/TLS-терминацию или VPN; если это невозможно и используется открытый порт, создайте отдельный случайный пароль для каждого эфира, подключайтесь только из доверенной сети и отзывайте реквизиты сразу после эфира. В BUTT выберите сервер Icecast, MP3, имя пользователя `source`; полный путь mount и одноразовый пароль скопируйте из студии. Источник нормализуется через FFmpeg в MP3, поэтому `FFMPEG_PATH` должен указывать на установленный FFmpeg. Не выставляйте наружу внутренний HTTP listener (`ICECAST_INGEST_HOST=127.0.0.1`, `ICECAST_INGEST_PORT=8006`) или Harbor `8005`.

Пример отдельных Nginx location для внешних DJ-входов (замените домен и настройте TLS в `server`):

```nginx
location ~ ^/dj-[A-Za-z0-9_-]+/whip$ {
  proxy_pass http://127.0.0.1:8889;
  proxy_http_version 1.1;
  proxy_buffering off;
}

```

Для публичного радио откройте только необходимые listener-порты; Harbor `8005` закройте входящим firewall-правилом, а telnet `1234`, MediaMTX API `9997` и RTSP `8554` оставьте на loopback. При завершении внешнего эфира остановите публикацию в OBS/BUTT тоже: учётные данные немедленно отзываются для новых соединений, но RTMP-соединение уже подключённого OBS нужно остановить в самом OBS.

### Диагностика

- Проверить веб-приложение: `curl http://127.0.0.1:3000/api/health` и `curl http://127.0.0.1:3000/api/nowplaying`.
- Проверить вход BUTT через Liquidsoap: `printf 'dj_live.status\n' | nc -w 2 127.0.0.1 1234`. Ответ `source client connected` означает, что вход подключён; `no source client connected` — что активного источника нет.
- Посмотреть журналы на Linux: `journalctl -u imperialradio.service -f` и `journalctl -u imperialradio-liquidsoap.service -f`. Ошибки декодирования входного аудио появляются в журнале приложения; переход между DJ и AutoDJ — в журнале Liquidsoap.
- Если BUTT показывает `Connected`, но звук не попадает в эфир, сначала проверьте, что двигается индикатор входного уровня, в BUTT выбран Icecast и в студии используются актуальные путь и пароль. После смены реквизитов остановите старую передачу в BUTT и запустите её с новыми данными.
- Если после обрыва не слышно радио, проверьте, что плеер сайта не поставлен на паузу. После первого нажатия «Играть» плеер сам повторяет соединение при сетевом сбое; ручная пауза отключает повторы.

## Эндпоинты
- `GET /` — публичная страница (плеер)
- `GET /stream` — проксированный поток Icecast
- `GET /api/nowplaying` — JSON с текущим треком
- `GET /api/health` — health
- `GET /login` — форма входа для администратора и DJ
- `GET /admin` — панель главного администратора
- `GET /dj` — панель диджея
- `POST /api/auth/login`, `POST /api/auth/logout` — создание и завершение сессии
- `/api/admin/djs` — управление учётными записями DJ (только супер-администратор)
- `/api/admin/services` — статусы служб радио; `POST /api/admin/services/:id/restart` — перезапуск разрешённой службы (только супер-администратор)
- `/api/dj/playlists` и `/api/dj/on-air/*` — личные плейлисты и управление слотом эфира, микрофоном и общей громкостью (только DJ)
- `/api/dj/queue` — список следующих треков текущего плейлистного эфира; `POST` добавляет трек, `PUT` переставляет, `DELETE` удаляет (только владелец эфира)
- `POST /api/admin/upload/music`
- `POST /api/admin/upload/jingle`

## Пример Nginx
```
server {
  listen 443 ssl;
  server_name example.com;

  location / {
    proxy_pass http://127.0.0.1:3000;
  }

  location /stream {
    proxy_pass http://127.0.0.1:3000/stream;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_request_buffering off;
    proxy_read_timeout 1h;
    proxy_send_timeout 1h;
  }
}
```

## Примечания
- `/api/nowplaying` использует in‑memory кэш с TTL `NOWPLAYING_CACHE_MS`.
- Панели и API требуют сессионную авторизацию; сессии хранят только хеш токена и имеют ограниченный срок действия.
- Логирование по умолчанию `LOG_LEVEL=silent`.

## Политика контента и прав

Ниже - политика для легального использования контента.

### Использование контента
- В эфире размещается только контент, на который у администрации станции есть права, лицензии или письменные разрешения правообладателей.
- Если права отсутствуют, контент не должен размещаться в эфире.
- Ответственность за соблюдение лицензий несёт владелец станции.

### Правообладателям (Notice & Takedown)
Если вы являетесь правообладателем и считаете, что ваш контент используется без разрешения:
- отправьте обращение с указанием трека, доказательством прав и способом связи;
- мы рассмотрим обращение и, при необходимости, удалим контент.
