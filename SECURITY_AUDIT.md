# Imperial Radio — аудит, исправления и ограничения

Дата: 11 ноября 2026 года. Область: ZIP-архив проекта, frontend HTML/JS, TypeScript API, SQLite, Icecast ingress, MediaMTX, Liquidsoap, службы перезапуска. Проверка исходного кода статическая + локальные автономные smoke-тесты. Аудит не является пентестом работающего VPS.

## Исправлено в поставляемом архиве

| Приоритет | Область | Проблема | Исправление |
|---|---|---|---|
| Высокий | Публичный плеер | Название текущего трека из Icecast вставлялось как HTML в историю прослушивания (DOM XSS) | DOM-узлы и `textContent`, прежняя структура и CSS сохранены |
| Высокий | Админка | Исполнители из `localStorage` напрямую вставлялись в HTML атрибута `value` | Вместо HTML-шаблона создаются `<option>` с `option.value` |
| Высокий | Загрузка | Частично загруженные файлы могли оставаться в фонотеке; превышение лимита могло завершиться без ошибки | Проверка `truncated` и удаление файла при любой ошибке записи |
| Высокий | Liquidsoap | В конфигурации раскрыт пароль источника Icecast, внутренний ingress-секрет задан заглушкой, Harbor не ограничен loopback | Пароли берутся из окружения; без реальных секретов запуск прекращается; `harbor.bind_addr=127.0.0.1` |
| Средний | Liquidsoap | Каталоги `C:/radio/...` не совпадают с Linux `MUSIC_DIR`/`JINGLES_DIR`; пустые джинглы приводили к лишней тишине | Пути из окружения; fallible-источники вместо `mksafe(jingles)`; прежнее соотношение 8:1 сохранено |
| Средний | Liquidsoap API | Команда могла ложно считаться успешной после 300 мс без завершающего `END` | Требуется полный ответ, ограничение 64 KiB и сетевой таймаут |
| Средний | Icecast ingress | Разделение HTTP-заголовка на TCP-пакеты приводило к разрыву потока | Буфер заголовка до CRLFCRLF, ограничение размера, пауза до готовности FFmpeg |
| Средний | FFmpeg relay | Дублирование процессов при одновременных оповещениях и гонка stop/start | Дедупликация запуска `starting`, ожидание активирующегося процесса при остановке |
| Средний | Fastify / busboy | Known DoS при слишком длинном multipart boundary в закреплённом `@fastify/busboy@3.2.0` | Ранний отказ HTTP 400 при boundary длиннее 70 символов (временная защита, обновление пакета всё ещё необходимо) |
| Низкий | API | Необработанные типы имени файла в admin queue/delete могли возвращать 500 | Zod-валидация с HTTP 400 и прежним кодом ошибки |
| Низкий | API | Отсутствуют базовые защитные заголовки | `nosniff`, запрет iframe, Referrer-Policy |
| Низкий | SQLite | `getPlaylist` просматривал все плейлисты пользователя | Прямая выборка по `(user_id,id)`, очистка старых сессий раз в 100 логинов, закрытие базы при завершении |
| Средний | Linux deploy | README ссылался на отсутствующие root-owned helper/socket/service для кнопки перезапуска | В `deploy/` добавлены ограниченный allowlist helper и systemd units; необходимы ручная установка и проверка |

## Риски, не закрытые этим патчем

1. **Зависимости.** `fastify@4.29.1` в неподдерживаемой ветке 4.x, `@fastify/busboy@3.2.0` (CVE-2026-19484 и другие), `undici@6.23.0` (например GHSA-xjj6-f33q-929c), `vitest@2.1.9` имеют опубликованные security advisories. Несовместимый major upgrade без доступа к registry/полной тестовой среде не проводился. Потребуется отдельное обновление зависимостей и lock-файла, а для Fastify — миграция со связанными плагинами. Не выдавать эту сборку за полностью защищённую от всех известных CVE.
2. **Внешние входы.** Raw Icecast SOURCE на `8007` и RTMP на `1935` не обеспечивают транспортную конфиденциальность сами по себе. Ограничьте firewall/VPN/TLS-терминацией. MediaMTX `8889` и UDP WebRTC должны быть настроены с реальными доменами и прокси.
3. **Непроверенный реальный эфир.** В среде аудита отсутствуют Liquidsoap, MediaMTX, Icecast, FFmpeg и запущенные systemd units. Не проводились runtime-проверка `.liq` на установленной версии и сквозная передача звука OBS/BUTT → слушатели.
4. **Npm registry недоступен.** `npm ci` не завершился из-за отсутствия доступа к registry и пакета `zod`; соответственно `npm run build`, `npm test`, `npm audit` с полноценными зависимостями не подтверждены. `dist/` обновлён транспиляцией глобального TypeScript, без семантической type-checking — обязательно повторить стандартную сборку в CI.
5. **Секреты из старого файла.** Пароль Icecast, который находился в загруженном `liquidsoap.liq`, следует считать скомпрометированным и **сменить** в действующем Icecast2. Любые реальные секреты предыдущего развёртывания не были доступны в архиве и не могут быть заменены на сервере автоматически.
6. **Системные настройки.** Для `/api/ingest/auth` и `/api/ingest/state` используется локальный доступ по IP. Убедитесь, что reverse proxy не публикует эти endpoint и что правила прокси корректно задают заголовки клиента; лучше вынести их в отдельный локальный listener/добавить аутентифицированный межсервисный callback в следующей версии.

## Подтверждённые локальные проверки

- Синтаксис 24 TypeScript исходников проверен парсером TypeScript, соответствующий ESM JavaScript обновлён в `dist`.
- Встроенные скрипты всех HTML-страниц прошли `node --check`, HTML/CSS и изображения не изменялись стилистически.
- Отдельный Node smoke-test проверил успешный upload, отказ от truncated upload и удаление обрезанного файла.
- Python helper скомпилирован `py_compile`, проверена блокировка произвольных идентификаторов служб.
- Добавлены Vitest регрессионные тесты (их выполнение требует `npm ci`).

## Порядок безопасного внедрения

1. Сохранить копии текущей базы SQLite (`.sqlite`, `-wal`, `-shm` при остановленной службе), каталогов музыки, `.env`, конфигурации Icecast/MediaMTX/Liquidsoap и systemd units. Не перезаписывать пользовательские данные архивом.
2. Ротировать пароль Icecast source, выбрать отдельный `LIVE_INGRESS_PASSWORD`; настроить защищённый `EnvironmentFile` именно службы Liquidsoap (см. README), сверить пути каталогов и порт. Секреты не хранить в git.
3. В среде с доступными npm и аудиосервисами выполнить `npm ci`, `npm audit --omit=dev`, `npm run build`, `npm test` и `liquidsoap --check /путь/liquidsoap.liq` с правильным окружением.
4. Проверить воспроизведение AutoDJ без джинглов и с ними, очередь next/queue/DJ, volume, микрофон WHIP, переключение RTMP/BUTT, reconnection, ограничения ролей admin/DJ, отзыв токенов при остановке.
5. Включать изменения поочерёдно с резервным планом отката и мониторингом журналов. Не обновлять работающий сервер без проверки версии Liquidsoap и компонентов.
